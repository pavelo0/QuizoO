# 5. Руководство пользователя

Настоящее руководство описывает порядок работы с веб-приложением **QuizoO** и предназначено для конечных пользователей: авторов учебных модулей и участников, которые проходят занятия. Для работы достаточно современного браузера с поддержкой JavaScript; установка отдельного клиентского приложения не требуется.

---

## 5.1 Лендинг и доступ к сервису

Корень сайта (`/`) отображает публичную страницу-лендинг для неавторизованных посетителей. Отсюда можно перейти к регистрации или входу. Авторизованный пользователь при обращении к корню перенаправляется в рабочую область приложения (`/app`).

---

## 5.2 Регистрация

Для создания учётной записи необходимо открыть страницу **`/auth/register`**, указать адрес электронной почты, пароль (не короче установленного на сервере минимума, в конфигурации проекта — не менее 8 символов) и при желании отображаемое имя.

После отправки формы система создаёт учётную запись со статусом «email не подтверждён» и выдаёт **код подтверждения** (обычно шестизначный). В типовой разработческой конфигурации код записывается в журнал сервера; при специальной настройке окружения код может дублироваться в ответе API для отладки. Для завершения регистрации нужно ввести код на экране подтверждения (**верификация email**). До подтверждения адреса вход по паролю недоступен.

При необходимости можно запросить повторную отправку кода (соответствующая операция на клиенте обращается к API повторной выдачи кода).

---

## 5.3 Аутентификация

Вход выполняется на странице **`/auth/login`**: указываются email и пароль, опционально отмечается запоминание сессии (**remember me**). После успешного входа браузер получает **httpOnly cookie** с JWT; интерфейс открывает главную страницу приложения **`/app`** (дашборд).

Отдельного «refresh-токена» в проекте нет: при истечении срока действия JWT пользователю потребуется войти снова. Срок жизни сессии зависит от выбора «запомнить меня» при входе (в конфигурации бэкенда задаются отдельные длительности для короткой и длинной сессии).

Заблокированная учётная запись не может войти в систему (решение принимает администратор).

---

## 5.4 Выход из системы

Выход выполняется из профиля или через доступное в интерфейсе действие «Выйти»: сервер сбрасывает cookie сессии, после чего защищённые разделы становятся недоступны до повторного входа.

---

## 5.5 Восстановление пароля

На странице **`/auth/forgot-password`** можно запросить код для сброса пароля на указанный email. Аналогично регистрации, доставка кода в учебной среде может осуществляться через журнал сервера. После получения кода пользователь задаёт новый пароль через API сброса; при успехе может быть автоматически установлена новая сессия.

---

## 5.6 Вход через Google

Доступен сценарий **OAuth 2.0 / OpenID Connect** с провайдером Google: пользователь перенаправляется на страницу согласия Google, после успешной авторизации возвращается в приложение; обработка завершения происходит на маршруте **`/auth/oauth/callback`**. Учётная запись связывается с профилем Google; отдельное подтверждение email паролем для этого сценария может не требоваться в зависимости от политики сервера.

---

## 5.7 Первичная настройка (онбординг)

После первого входа пользователь может быть направлен на страницу **`/app/onboarding`** для краткого знакомства с сервисом или уточнения стартовых данных (конкретный состав шагов задаётся клиентским приложением).

---

## 5.8 Общая навигация в приложении

Авторизованная рабочая зона располагается под префиксом **`/app`** и использует боковое меню (или компактный вариант навигации на узких экранах). Доступны переходы к дашборду, разделу статистики, созданию модулей и профилю. Для пользователей с ролью **ADMIN** в меню появляются пункты администрирования.

Интерфейс поддерживает переключение **темы** (светлая / тёмная) и **языка** отображения текстов, если эти элементы включены в сборке.

---

## 5.9 Дашборд

Страница **`/app`** (главная после входа) показывает сводку по модулям пользователя и недавнюю активность: создание и прохождение модулей отображаются в обобщённом виде. Отсюда можно перейти к нужному модулю или начать создание нового.

---

## 5.10 Просмотр и редактирование профиля

Профиль открывается по адресу **`/app/profile`** (или через ссылку на профиль в меню / аватар).

На странице профиля отображаются данные учётной записи (email, имя, роль). Пользователь может:

- изменить **отображаемое имя** и сохранить изменения;
- загрузить, заменить или удалить **аватар** (файл принимается сервером в ограниченном формате и размере — конкретные ограничения задаются клиентской валидацией и API);
- открыть форму **смены пароля** (текущий пароль и новый);
- инициировать **смену email** (обычно требуется подтверждение текущим паролем и повторная верификация нового адреса по коду).

Часть операций завершается обновлением данных пользователя в интерфейсе без повторного входа.

---

## 5.11 Создание учебного модуля

Модули бывают двух типов:

- **модуль карточек (flashcard)** — термин на лицевой стороне, определение на обороте;
- **модуль викторины (quiz)** — вопросы с вариантами ответа, свободным вводом или заданиями на сопоставление пар.

Старт создания выполняется с дашборда или через маршрут **`/app/modules/create`** с параметром типа, например:

- `?type=FLASHCARD` — создание модуля карточек;
- `?type=QUIZ` — создание модуля викторины.

Клиент создаёт черновик модуля на сервере и перенаправляет на соответствующий **редактор**.

---

## 5.12 Редактор модуля карточек

Редактирование доступно по пути **`/app/modules/{moduleId}/edit`**. Пользователь добавляет, изменяет и удаляет карточки, задаёт заголовок и описание модуля. Порядок карточек можно менять (в интерфейсе используется перетаскивание). Изменения сохраняются через API модуля.

---

## 5.13 Занятия в режиме карточек

Режим прохождения открывается по адресу **`/app/modules/{moduleId}/flash-study`**. Пользователь просматривает карточки и отмечает, какие позиции усвоены, а какие требуют повторения. По завершении сессии на сервер отправляется сводка (количество карточек, сколько отмечено как известные / неизвестные, время завершения) для учёта статистики.

---

## 5.14 Редактор модуля викторины

Редактор расположен по пути **`/app/modules/{moduleId}/quiz-edit`**. Для каждого вопроса задаются формулировка и тип:

- **выбор** из вариантов (в том числе с разрешением нескольких верных ответов, если это включено для вопроса);
- **свободный текст**;
- **сопоставление пар** (левые и правые элементы).

К отдельным вопросам можно прикрепить **изображение**: загрузка и удаление выполняются через соответствующие API; изображение отображается при прохождении викторины.

Метаданные модуля (название, описание) также редактируются на стороне клиента и сохраняются на сервере.

При использовании **экспорта/импорта JSON** для викторин следует учитывать ограничение: изображения вопросов в JSON не включаются. После импорта вопросы и текстовые данные восстанавливаются, но изображения нужно загрузить повторно вручную.

---

## 5.15 Прохождение викторины

Страница занятий: **`/app/modules/{moduleId}/quiz-study`**. Пользователь последовательно отвечает на вопросы; по завершении отправляется набор ответов, сервер выставляет оценку / результат и создаёт запись **сессии квиза**. При необходимости можно открыть детали последней или выбранной сессии (идентификатор сессии используется в запросах API).

---

## 5.16 Удаление модуля

Владелец модуля может удалить его через действие в интерфейсе (как правило, с экрана дашборда или карточки модуля). Удаление модуля на стороне базы данных каскадно удаляет связанные карточки, вопросы, варианты, пары сопоставления и сохранённые сессии обучения.

---

## 5.17 Статистика

Раздел **`/app/statistics`** обобщает данные об активности и результатах обучения пользователя на основе тех же источников, что и дашборд (сводки и недавние события). Конкретные показатели и графики зависят от версии клиентского приложения.

---

## 5.18 Администрирование (роль ADMIN)

Пользователям с ролью **ADMIN** доступны маршруты:

- **`/app/admin`** — обзорная панель;
- **`/app/admin/users`** — список пользователей, **блокировка и разблокировка** учётных записей;
- **`/app/admin/modules`** — обзор модулей всех пользователей;
- **`/app/admin/analytics`** — аналитические показатели для администратора.

Операции выполняются через защищённые API; обычный пользователь без роли ADMIN эти страницы не видит и не может открыть принудительно через прямой URL.

---

## 5.19 Ограничения и замечания по работе в браузере

- Приложение рассчитано на работу по **HTTPS** или локальной разработке с согласованными настройками **CORS** и cookie.
- Для авторизованных запросов используется cookie **`quizoo_access_token`** (или актуальное имя из конфигурации деплоя); доступ к API с других сайтов без учёта политики cookie может быть ограничен.
- **Push-уведомления и WebSocket** в текущей версии проекта для пользовательских событий не описываются — обновление данных происходит при загрузке страниц и после действий пользователя.

---

## 5.20 Выводы по разделу

В результате изложены:

- порядок **регистрации с подтверждением email по коду**, **входа**, **выхода**, **сброса пароля** и **входа через Google**;
- работа с **профилем** (имя, аватар, пароль, смена email);
- структура приложения после входа: **дашборд**, **статистика**, **онбординг**;
- полный цикл работы с **учебными модулями**: создание черновика, редактирование **карточек** и **викторины** (включая типы вопросов и изображения), **прохождение** занятий и сохранение **сессий**;
- **удаление модулей** и каскадное удаление связанных данных;
- возможности **администратора**: просмотр пользователей и модулей, блокировка учётных записей, аналитика.

Руководство привязано к фактическим маршрутам SPA (`frontend/src/router.tsx`) и к описанию REST API с префиксом `/api`, приведённому в технической документации проекта. При необходимости иллюстрации интерфейса (скриншоты экранов) добавляются к соответствующим подразделам отдельно.
