Тема: Веб-приложение «QuizoO» для создания и прохождения учебных тестов

1. Срок сдачи студентом законченной работы: «21 декабря 2026 г.»
2. Исходные данные к проекту:
   2.1. Функционально веб-приложение должно поддерживать роли «Гость», «Пользователь» и «Администратор».
   Функции пользователя с ролью «Гость»:
    просмотр публичной ознакомительной страницы;
    регистрация;
    аутентификация (вход по электронной почте и паролю);
    восстановление пароля;
    вход через внешний провайдер учётной записи (OAuth).
   Функции пользователя с ролью «Пользователь»:
    создание тематических наборов (папок) по учебной теме или предмету экзамена;
    редактирование и удаление собственного тематического набора;
    добавление в набор нескольких модулей типов «Карточки» и «Квиз», исключение модулей из набора;
    выборочное изучение отдельных модулей внутри набора (повторение конкретной темы, а не всего материала подряд);
    просмотр прогресса по тематическому набору (доля модулей, с которыми пользователь уже работал);
    создание учебного модуля типа «Карточки» или «Квиз»;
    редактирование и удаление собственного модуля;
    добавление, редактирование, изменение порядка и удаление карточек;
    добавление, редактирование и удаление вопросов квиза;
    поддержка типов вопросов: выбор варианта ответа (один или несколько), ввод текстового ответа, сопоставление пар, упорядочивание элементов;
    указание допустимых вариантов текстового ответа и проверка ответов на стороне сервера с нормализацией ввода;
    прикрепление изображения к вопросу квиза;
    экспорт и импорт содержимого модуля в формате JSON;
    прохождение режима обучения «Карточки» с самооценкой «знал / не знал» и повтором незнакомых карточек;
    прохождение режима обучения «Квиз» с автоматической проверкой ответов;
    просмотр результатов текущей сессии и разбора ошибок (включая эталонный ответ);
    повторное прохождение только вопросов с ошибками;
    создание занятия по модулю типа «Квиз»: выдача короткого кода, просмотр журнала попыток участников, срок выполнения;
    присоединение к занятию по коду и прохождение выданного квиза;
    начисление очков опыта за учебную активность: прохождение карточек и квиза, повтор ошибок, проведение занятия;
    просмотр статистики и истории прохождений по модулям и тематическим наборам;
    просмотр в профиле уровня, накопленных очков опыта и полученных достижений с указанием условий их получения;
    редактирование профиля (имя пользователя, электронная почта, пароль, аватар);
    выход из аккаунта.
   Функции пользователя с ролью «Администратор»:
    просмотр сводной информации по платформе;
    просмотр списка всех пользователей;
    блокировка и разблокировка пользователей;
    просмотр всех модулей платформы;
    удаление любого модуля.

2.2. Программное средство должно представлять собой веб-приложение и взаимодействовать с базой данных PostgreSQL. Проект должен быть разработан с использованием платформы Node.js и фреймворка NestJS для серверной части, библиотеки React — для клиентской (одностраничное приложение, SPA); взаимодействие между клиентом и сервером — через RESTful API. Представление, бизнес-логика и работа с данными должны быть максимально независимы друг от друга для возможности дальнейшего расширения приложения. Развёртывание приложения должно осуществляться с использованием Docker Compose и прокси-сервера Nginx. Веб-приложение должно быть логически завершённым, а управление программой – интуитивно понятным и удобным. Листинги проекта должны содержать необходимые комментарии.
