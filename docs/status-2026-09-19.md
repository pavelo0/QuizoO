## 2. Что имеем по проекту сейчас (полное ядро)

Готовый full-stack продукт: персональная платформа закрепления знаний (карточки + квизы).

**Стек:** React 19 + Vite + TypeScript, NestJS + Prisma + PostgreSQL, JWT в httpOnly cookie, Docker Compose + Nginx (HTTPS).

### Аккаунты и доступ

- лендинг, регистрация, вход, выход, «запомнить меня»
- верификация email по коду, сброс пароля
- Google OAuth
- профиль: username, email, пароль, аватар
- роли Guest / User / Admin; guards на клиенте и API
- админ: список пользователей, блок/разблок, все модули, удаление модуля, сводка

### Обучение

- модули двух типов: `FLASHCARD` и `QUIZ` (CRUD, только свои)
- карточки: редактор, порядок, режим «знал / не знал», повтор, сессия
- квиз: `CHOICE` (один и несколько ответов), `TEXT`, `MATCHING`, **`ORDERING`**
- картинка к вопросу
- JSON import/export контента модуля
- серверная проверка ответов, балл, разбор сессии, история
- дашборд, лента активности, страница статистики
- i18n ru/en, светлая/тёмная тема, таймер сессии квиза

### Инженерия

- монорепозиторий, ESLint / Prettier / Husky
- Jest: modules service, answer-normalizer, ordering-grader
- frontend: скелет **FSD** (`app` / `pages` / `widgets` / `features` / `entities` / `shared`), часть legacy-путей ещё жива

Этого **уже достаточно**, чтобы система была законченным учебным веб-приложением, а не прототипом.

## 4. Принцип развилки: сейчас vs диплом

**Сейчас** — довести то, что уже начато на практике, до «можно сдавать»: один понятный новый функциональный слой поверх курсового ядра + аккуратная записка. Без WebSocket, без AI, без соцсети.

**Диплом** — смена масштаба продукта: социальность, реальное время, умное расписание, внешние интеграции. Это должно **остаться несделанным** сейчас, иначе на диплом не останется предмета.

## 5. Что стоит продолжить сейчас (текущая работа)

Цель: объём достаточный, но не съедает диплом.

### Обязательный минимум (рекомендуется)

1. **Дожать практику в пользовательском сценарии**  
   Сквозной сценарий для защиты: TEXT с синонимами (`Париж` / `Paris`) + вопрос ORDERING с DnD + разбор результата. Это и есть «новое» относительно первого курсового.

2. **Канонический ответ в разборе ошибок (B.3)**  
   Маленькая, но видимая доработка: после ошибки показывать эталон «Париж», а не сырой ввод. Логичное завершение фазы B, не диплом.

3. **Тесты на уже существующие типы**  
   Unit: MATCHING и multi-CHOICE. Типы давно в продукте, тестов нет. Усиливает главу «тестирование» без новых фич.

4. **Записка/ТЗ под фактический код**  
   Зафиксировать 4 типа вопросов, normalizer, FSD, Docker. Не копировать `archive/checklist.md` апреля.

### Можно взять 1 пункт «на оценку выше» (не все сразу)

Выбрать **одно**:

- **TRUE_FALSE** — самый дешёвый новый тип вопроса (2 варианта, почти CHOICE). Для курсовой хватит; FILL_BLANK / NUMERIC оставить диплому или не брать.
- **Лёгкая нарезка QuizEditor** — вынести поля ORDERING/TEXT в features (уже начато в FSD). Для главы «архитектура», без смены продукта.
- **Показ прогресса TEXT/ORDERING в статистике** — если на защите спросят «что изменилось для пользователя».

Не брать пакетом: новый тип + полный FSD cleanup + декомпозиция всего `modules.service.ts`. Это уже объём диплома по инженерии.

### Не делать сейчас

- Sentry «для галочки» без продакшен-DSN
- Playwright на весь продукт (достаточно ручных сценариев + Jest grading)
- Fuzzy-опечатки (Levenshtein) — спорная педагогика, лучше диплом или не делать
- Refresh JWT, полноценный SMTP, CI GitHub Actions — инфраструктура диплома

## 6. Что оставить и добавить на диплом

Крупные темы из [`project-overview.md`](./projectOverview.md) и `TODO.md`. Их **не начинать** в текущей работе, кроме упоминания в «перспективах».

### Ядро диплома (взять 2–3, не все)

| Тема                                         | Почему это диплом                             | Зависимость от нынешнего ядра     |
| -------------------------------------------- | --------------------------------------------- | --------------------------------- |
| **Live-мультиплеер (WebSocket / Socket.io)** | Новая архитектура, комнаты, таймер, лидерборд | QUIZ + серверная проверка         |
| **Spaced repetition**                        | Отдельный алгоритм и модель расписания        | flashcard-сессии «знал / не знал» |
| **Публичные модули + поиск + копирование**   | Социальный слой, права, модерация             | CRUD модулей, роли                |

### Дополнительно на диплом (по времени)

- режим «Спринт» (60 сек) + рекорды по модулю
- FILL_BLANK / MULTI_TEXT / NUMERIC
- расширенная аналитика: heatmap, слабые карточки, сравнение с другими
- AI-генерация вопросов из текста (внешний API)
- декомпозиция `modules.service.ts` + DTO на все quiz-эндпоинты
- Playwright e2e + CI
- Sentry, SMTP, refresh-токены
- добить FSD (D.5): убрать proxy, AuthContext, god-pages

Мультиплеер — лучший «технический якорь» диплома. Публичные модули — лучший «продуктовый». SRS — лучший «алгоритмический». Достаточно **одного якоря + одного сопутствующего**.

## 7. Дополнительные идеи (не в старом overview)

Имеет смысл держать в уме, но не смешивать со «сейчас».

**Для текущей работы (мелкие, если останется время)**

- лимит карточек/вопросов объяснить в UI, а не только константой
- в разборе ORDERING подсвечивать позиции, где порядок совпал (partial credit уже есть на бэке — показать в UI)
- demo-аккаунт на лендинге «войти как демо» (seed уже есть)

**Для диплома**

- дедлайны / цели «повторить модуль до даты» (`useDeadlineCountdown` уже намекает)
- шаринг модуля по ссылке-приглашению без полноценного каталога — промежуточный шаг к публичным модулям; лучше не делать сейчас, чтобы не срезать дипломную «социалку»
- офлайн-пакет / PWA — спорно для кафедры, низкий приоритет
- группы/классы (учитель видит результаты учеников) — сильнее публичного каталога, но это уже LMS; только если диплом сознательно уходит в EdTech, а не в Quizlet-клон
