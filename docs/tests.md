# 4 Тестирование

## 4.1 Цели и подход к тестированию

Для проекта **QuizoO** тестирование организовано в двух слоях:

1. **Функциональное (ручное, black-box)** — проверка основных пользовательских сценариев через UI и API без привязки к внутренней реализации.
2. **Автоматизированное (Jest, backend)** — проверка бизнес-логики сервисов и корректной работы контроллеров NestJS с изоляцией зависимостей через `jest.fn()`.

Основная цель раздела — подтвердить, что система корректно:

- регистрирует и аутентифицирует пользователей;
- управляет учебными модулями типов `FLASHCARD` и `QUIZ`;
- валидирует ответы и считает результат квиза;
- обрабатывает загрузку изображений к вопросам;
- возвращает данные дашборда и активности.

## 4.3 Автоматизированное тестирование (что реализовано в проекте)

В рамках работы реализованы и запущены backend-тесты на Jest.  
Используемые команды:

- `npm --workspace backend test`
- `npm --workspace backend test -- modules`
- `npm --workspace backend run test:cov`

В ходе работы по тестированию QuizoO выполнено следующее:

Таким образом, критичный функционал учебных модулей, прохождения и проверки результатов подтвержден ручными и автоматизированными тестами. Для следующего этапа рекомендуется расширить автоматизированное покрытие на `AuthService` и `UsersService`, чтобы повысить общее покрытие backend-части.
